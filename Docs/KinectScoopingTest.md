# Kinectで餌を掬うテスト

`Assets/Scenes/Sandbox/ScoopingTest.unity` は、ダイバーの一人称視点で右腕を動かす独立したSandboxです。
手の開閉を調べる `KinectTest.unity` とそのコードは維持しています。

## 操作

既定では **Keyboard Test Mode** が有効です。Kinectを接続せず、CPUのみのノートPCでも掬い・魚が食べる流れを確認できます。Play後にGame Viewを一度クリックしてキー入力を受け取らせます。

| キー | 動作 |
| --- | --- |
| `W` / `S` | 手を前／後ろへ動かす |
| `A` / `D` | 手を左／右へ動かす |
| `E` / `Q` | 手を上／下へ動かす |
| `Left Shift` | 手の移動を速くする |
| `F` | 餌が皿に戻っている間に次の餌色を選び直す |
| `Backspace` | 手と餌を初期状態へ戻す |

開始時の仮想手は皿の餌の位置です。`E`で約6 cm持ち上げ、`W`で前へ差し出します。餌は一粒のままです。差し出して約5秒待つと一匹だけが餌を食べ、その魚の色が餌色に変わります。食べる魚は一回ごとに交代します。接触していない場合は`WASD`で少し位置を調整してください。餌を戻す場合は手を皿の位置へ戻します。

Kinect実機を使う場合は、Inspectorで **Keyboard Test Mode** を無効にしてPlayします。キーボードテスト中は`AzureKinectSkeletonView`をPlay中のみ無効化するため、Azure Kinect SDKのロード・センサー初期化は行いません。Playを終了するとシーン上の有効状態は元に戻ります。

手のモデルは掬う形で固定しています。実際の指の形・掌の向きは入力条件ではありません。
現在は右腕のみを操作します。カメラは正面を向いた固定FPVで、頭の動きには追従しません。

掌の中心に半径6.5 cmのSphereCollider、餌に見た目と同じサイズのBoxColliderを置き、`Physics.ComputePenetration` で毎フレーム接触を検査します。物理の押し返しやRigidbodyの移動には依存しません。画面上で重なっても奥行きが離れていれば未接触です。接触後に水平12 cmより離れる、下へ12 cmより離れる、または追跡が失われると未完了の掬い動作を解除します。

## 骨格と表示

- `KinectScoopPose` が胸・右肩・肘・手首を受け取り、胸を基準にメートル単位でカメラ空間へ写します。自分の右へ動かすと画面の右へ、Kinectへ近づけると海の前方へ動きます。
- 手位置は、手首から肘→手首の方向へ9 cm延長した位置を基本とします。SDKの手関節が信頼度・距離・方向・急な変化の検査を通る場合、計測した位置を混合します。約0.1秒の平滑化を行います。
- 手首自体の位置ずれや骨格の誤推定は残り得ます。SDKの信頼度は正確さの保証ではありません。
- 胸・肩・肘・手首が使えない、またはフレームが0.35秒以上古い場合は操作を停止します。既に持った餌は保持し、5秒の提示は再計測します。手の表示は最後の位置に残ります。
- 一時的に見失っても同じ身体IDを維持します。2秒以上身体が見つからない場合は選択を解除し、身体が1人だけになったときに再取得します。
- RGBの手認識とgrab判定はこのシーンでは起動しません。

`KinectScoopPose` のInspectorで胸の基準位置・手首からの延長長・平滑化時間を調整できます。
初期の胸基準はカメラから `(0, -0.38, 0.25)` m、皿は `(0.28, -0.30, 0.48)` mです。
実機の手触り確認では、まず左右・上下・前後の対応、皿への届きやすさ、胸の前での途切れを確認してください。

## 手のアセット

[Stylized - Simple Hands (221297)](https://assetstore.unity.com/packages/3d/characters/stylized-simple-hands-221297) を `Assets/ThirdParty/SimpleHands/` に同梱しています。モデル・テクスチャ・Prefabと既存の `.meta` を追跡し、シーンが参照するGUIDを維持しています。
モデル・テクスチャ・付属PDFはGit LFSで管理しています。clone後に `git lfs pull` を実行して実体を取得してください。Asset Storeからの別途インポートは不要です。

WhiteHandの手首がモデル原点です。表示スケールを0.165、ローカルZ回転を180度にし、指ボーンを少し曲げて掌を上へ向けています。回転は左右反転とは別です。左右を複製する場合の鏡映は、この向きではモデルのローカルX軸が候補になりますが、左手の動作・描画は今回未検証です。
アセットのAnimatorはこのテストでは使用せず、シーン内のモデルから外しています。
手モデル、手の中心、餌、皿はそれぞれ独立したGameObjectです。

## 開発・確認

- `Tools > Under The Sea > Create Scooping Test` からEditor APIでシーンを作成できます。実行中、未保存のシーンがある場合、または既にScoopingTestが存在する場合は作成しません。既存シーンの調整はInspectorから行います。
- `ScoopPoseChecks.Run()` と `ScoopInteractionChecks.Run()` はUnity内で実行する純粋ロジックの検査です。`ScoopContactChecks.Run()` は実際のColliderの接触・非接触を検証します。実機精度のベンチマークではありません。
- `KinectScoopSandbox.DiagnosticInput` はEditorコードからの動作確認用です。通常の手動確認はInspectorのKeyboard Test Modeで行います。
- 日本語HUDは実行PCのYu Gothicを使います。このテストの対象はWindowsのUnity Editorです。

2026-10-27: 初版はテスト入力で取得・提示・魚の接近・消費・補充を確認したものの、ユーザーの実機操作では掬えないと判明しました。皿との距離・進入順序だけで判定していたため、掌と餌のCollider接触を使う方式へ変更しました。修正版の実機の手触りは再確認が必要です。
