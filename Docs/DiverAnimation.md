# Diverの通常・受信・泳ぎアニメーション

MainのDiverViewControllerがDiverAnimationControllerを自動追加します。既存Animator Controllerに登録された7本のクリップを名前から取得します。仮置きのTrigger/Boolや条件なし遷移には依存しません。元の.controller・FBX・シーンは変更しません。

| 用途 | クリップ |
| --- | --- |
| 通常待機・移動停止後 | Idle_roop |
| 泳ぐ | Swim |
| トランシーバーを聞く | Stop |
| 各遷移 | Idle2Swim / Swim2Idle / Idle2Stop / Stop2Idle |

Voskの確定結果が登録コマンドと一致したときだけ受信要求を出します。ただし前進要求中は泳ぎを優先し、受信要求を破棄してStopを割り込ませません。音量・音声入力開始・未登録語では発動しません。開発用キーの視点変更・前進・停止でも同じ受信要求を出すため、マイクなしでも確認できます。停止・衝突回避・実際の移動や視点変更はモーションを待ちません。餌やり・起動待ち・撤退はそれぞれの制御を優先します。

- 待機から受信：Idle → Idle2Stop → Stop → Stop2Idle → Idle。
- 移動中の受信：Swimを維持します。前進開始指示そのものの受信モーションも優先しません。向き直り待機を含めて前進要求中はIdle2Swim → Swimへ進みます。
- 通常の前進：Idle → Idle2Swim → Swim。通常停止：Swim → Swim2Idle → Idle。
- 減速中は移動速度を見て泳ぎを維持します。停止指示の受信モーションは減速後に再生できます。受信中に前進を指示した場合は、Stop2Idleを経て泳ぎへ切り替えます。Stopと遷移モーションは1回再生し、繰り返しません。
- 受信中の追加コマンドはクリップを先頭へ巻き戻しません。待機要求は最大1件にまとめ、長い再生待ちを作りません。
- 餌やり操作ロック中やAnimator無効化中はグラフを評価せず、右腕のKinect/キー追従を上書きしません。終了後はIdleから再開します。

Play中のDiverAnimationControllerで「現在のモーション」を確認できます。各クリップを直接指定することも可能です。Idleの初期速度は既存の設定に合わせ0.4、SwimとStopは1、遷移は1.5です。「受信姿勢を保つ最小秒数」はStopクリップ1周期より長く保持したい場合に使います。再生速度や最小秒数の変更はPlayを再実行して反映してください。設定を保存する場合はPlay前にDiverへコンポーネントを追加してください。

Play中は専用のPlayableGraphがAnimatorを駆動するため、AnimatorのController欄は一時的に空になります。元のControllerは保持しており、無効化・破棄時に戻します。クリップは複製せず、グラフは1個のみで終了時に破棄します。Root MotionはOFFにし、移動スクリプトとの二重移動を防ぎます。クリップ不足時はエラーを出して既存Animatorを維持します。

検証：C#の参照DLLコンパイルと、受信・通常待機・泳ぎ・遷移・受信中の停止・連続認識・餌やり復帰など22項目の独立テストを実施。Unityは起動しておらず、クリップの実読込、ブレンド、姿勢・一人称視点・Kinectとの重なりは未確認です。

初期化時に7本のクリップ名と長さ、切替時にモーション名・前進要求・移動速度を[DiverAnimation]でログ表示します。切替ログはInspectorの「モーション切替をログ表示」でOFFにできます。
