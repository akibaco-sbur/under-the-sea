# Kinect 手の開閉テスト

`Assets/Scenes/Sandbox/KinectTest.unity` は、Azure Kinect の右手の開閉を単体で調べるためのシーンです。餌や魚の処理には接続していません。右手の位置は Kinect の骨格、指の形は 1280×720 の RGB 画像から MediaPipe の3D手関節点を推定し、4本の指の曲がり方で判定します。

## 操作

1. [Azure Kinect のセットアップ](AzureKinectSandbox.md)に従い、SDK と Kinect を用意します。
2. Python をインストールした Windows で `Tools/SetupMediaPipe.ps1` を実行します。MediaPipe と公式モデルを `.Local/MediaPipe` に配置します。
3. `KinectTest.unity` を開いて Play し、Kinect の前で右手を見せます。キーボード操作は不要です。
4. 開く・握る・手を動かす操作を行い、手の画像、状態、数値を確認します。

左は depth 画像、中央は右手の depth 拡大図と RGB 画像です。depth の水色は面積スコアの計算に使った画素、RGB の水色の点は照合できた手の関節点です。アプリの認識コードは画像をメモリで処理し、画像の保存・アップロード処理を持ちません。MediaPipe ランタイムのテレメトリー通信は別に発生することがあります。

右側は `NOT FIST / FREE`、`CLOSED / GRAB`、`UNKNOWN / FREE` と判定理由です。灰色が非握り、緑が握り、暗い灰色が追跡不明です。Kinectの右手首をRGB座標へ投影してRGBの手首と照合し、手首が使えない場合は手の中心を使います。信頼度1（low）でもRGBへの入力は続けますが、RGBで利用可能な手が確認できない限りGRABにしません。対応する手がない、不正な関節点、異なる身体ID、0.75秒より古いRGB結果はGRABにしません。キー操作・開いた手の初期校正・前のGRABを保持する処理はありません。

照合は正規化座標の距離0.20以内の候補から選びます。候補が反対側の手首へ0.02以上近い場合は拒否し、左右の投影や候補同士の距離差が0.02以内なら曖昧としてUNKNOWNにします。これらは誤対応を減らすための暫定条件で、手の同一性を保証しません。

全画面で手が得られないときは、目標を中心とする360×360画素（720p時）の領域を別のIMAGE認識器で再検出します。切り出し座標を元画像へ戻し、同じ照合と反対手の拒否を適用します。全画面で既にFREEと判定できた手を切り出しでGRABに上書きせず、全画面で候補が競合している場合も切り出しだけで曖昧さを解消しません。

RGBのオレンジの十字は右手の目標、マゼンタは反対側の手首です。上部に骨格の信頼度、右パネルに認識元 `Full` / `Crop`、検出手数、`NoHand`・`OutsideTarget`・`OtherHand`・`Ambiguous` などUNKNOWNの理由を表示します。骨格入力の問題と指形の分類を分けて確認できます。

## 握りの判断理由

`Tools/HandPoseGeometry.py` を実機ワーカーとオフライン評価の両方から使用します。人差し指・中指・薬指・小指の各指について、次を計算します。

- `Chord ratio`: 指の付け根から指先までの直線距離 ÷ 指の3本の骨の長さの合計。直線なら1に近く、曲がると小さくなります。
- `Bend`: 手首・人差し指の付け根・小指の付け根で定義した掌面に対する、付け根から第2関節への骨の傾斜角。横方向に指を広げるだけでは増えません。

各指が「ratio ≤ 0.85」または「ratio ≤ 0.95 かつ Bend ≥ 45度」を満たし、**4本すべて**が成立したときだけGRABです。途中の関節だけでなく付け根で曲がる握りも扱います。親指は判定対象外で、親指だけ立てた握りもGRABになり得ます。これらは推定座標の幾何条件であり、確率やモデルの信頼度ではありません。

画面の旧カテゴリ名とスコアは比較表示のみです。`Closed_Fist` の65%閾値やdepth面積からGRABへ変更する処理はありません。数値と角度は座標の剛体回転・一様拡大に不変ですが、関節点を推定するモデル自体は視点・遮蔽の影響を受けます。

比較用に以前の depth 面積推定の状態、面積、比率、画素数と手の距離・速度も表示します。比率は平滑化した面積をパーと仮定した基準で割った値です。depth 推定だけは開始直後の約 0.4 秒を開いた手と仮定します。

depth画素数は奥行きによる大きさの変化を補正し、手首から遠い側を重く扱います。基準に対して88%未満が約0.2秒続くとCLOSED、96%を超える状態が約0.2秒続くとOPENになります。移動速度が0.35 m/sを超える間はdepthの状態を維持し、OPEN中は基準も更新します。この比較値はGRABを制御しません。

## 制約

開閉は Azure Kinect 標準 API ではなく推定です。RGBが暗い、手が小さい・隠れる、対応付けが不正確な場合には認識できません。複数の手が近接すると別の手を拾う可能性も残ります。指差し・部分握りなど多様な非グーの実写評価は未完了です。depth面積は肩などと重なると誤判定します。[録画評価の手順と結果](HandRecognitionBenchmark.md)を参照してください。録画での改善とライブ入力の精度は区別します。
