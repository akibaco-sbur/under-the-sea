# 手の開閉のオフライン評価

`Tools/BenchmarkHandRecognition.py` は保存済みの予測 CSV を、同じフレームのラベルと照合する。画像やモデルを実行せず、ラベルの補間や編集をしない。各入力の SHA-256、全体と条件別の件数を JSON に出力し、既存出力を上書きしない。Python 標準ライブラリのみを使う。

```powershell
python Tools/BenchmarkHandRecognition.py `
  --frames .Local/HandBenchmark/take-20261027-105336-8a_jdv55/Frames.csv `
  --labels .Local/HandBenchmark/take-20261027-105336-8a_jdv55/ReviewedLabels.csv `
  --prediction .Local/HandBenchmark/take-20261027-105336-8a_jdv55/RgbSampleResults.csv `
  --output .Local/HandBenchmark/Experiments/Audit/Example.json
```

`--prediction` を繰り返して方式を並べられる。予測CSVは `frame,predicted` を必須とし、値は `GRAB` / `NON_GRAB` / `UNKNOWN`（既存の `CLOSED` / `OPEN` も可）。既存のprobe CSVは `gesture,score` を0.65で従来通り判定する。全スコア対象フレームの予測がなければエラーとし、都合のよいサンプルだけで比較できないようにする。フレーム番号重複や利用可能なタイムスタンプ不一致もエラーとなる。

ラベルCSVの `reviewedLabel` は `OPEN` / `CLOSED` / `UNSCORED`。UNSCOREDは除外数を記録してスコアから除く。ラベルがないフレームは評価しない。`--labels` の代わりに `--provisional-probe` を明示すると、Frames.csv の PROBE にある指示ラベルを使えるが、これは各フレームの正解を確認したものではない。指示後の反応遅れや見えない手を含む可能性がある。未確認の値を精度や確定した再現率として報告しない。

- GRAB recall = CLOSEDのうちGRABの割合。UNKNOWNも分母に含む。
- false GRAB rate = OPENのうちGRABの割合。UNKNOWNも分母に含む。
- coverage = OPENまたはCLOSEDのうちUNKNOWN以外の割合。分母ゼロの比率はnull。

同一のラベルと対象フレームに対して各方式を採点し、方法ごとに手の対応付け・モデル・前処理・閾値を明記する。既存の固定座標による選択は手首や関節の骨格投影に基づくUnityの対応付けではなく、手の重なりで対象と別の手を拾う可能性がある。対象手の対応を映像とランドマークの両方で別途確認し、不確実な例を明示する。異なる対応付けの結果は分類器だけの差と解釈しない。

今回の目視サンプルは単一人物・単一環境の連続試行であり、隣接フレームは独立ではない。最新の握り指示のみの記録は陰性を含まず false GRAB rate を測れない。選択や調整に使った記録とは別の人物・距離・背景・回転・遮蔽を含む未使用のOPEN/CLOSED試行を、推論結果を見る前にフレーム選択・目視ラベル付けして評価する。オフラインの全フレーム処理はリアルタイムのフレーム欠落、遅延、追跡やUI表示を再現しない。

## 実ワーカーで再生する

`Tools/ReplayHandBenchmark.py` はUnityと同じRGBAバイナリプロトコルで `MediaPipeHandWorker.py` の子プロセスを実行する。各応答のIDと録画全体のフレーム数、正常終了を検証し、`Predictions.csv`・`Timing.json`・`WorkerStderr.log` を新規出力する。判定にはラベルや動作条件を渡さない。

```powershell
.Local/MediaPipe/Scripts/python.exe Tools/ReplayHandBenchmark.py `
  .Local/HandBenchmark/take-20261027-111355-fbruf2fd `
  .Local/HandBenchmark/Experiments/NewRun `
  --targets-csv .Local/HandBenchmark/Experiments/Runtime/ProxyTargets.csv
```

`--targets-csv` は各フレームの `frame,x,y,confidence`。正規化座標とconfidenceが正の場合のみ対象を指定する。固定座標の実験は `--target-x 0.45 --target-y 0.35` でもよいが、骨格追跡の実証ではない。既定解像度1280×720、`--width 640` で以前の縮小入力、`--stride 2` で隔フレームを評価できる。VIDEOの時刻は実機ワーカーと同じ提出連番×100msで、実時間のキューや追跡遅延は再現しない。

## 2026-10-27の改善比較

最新の録画のPROBE全600フレームを分母に固定した。見えにくい手や回転した手を除外していない。各セルはグー指示中にGRABとなった割合であり、フレームごとの正解を全件確認した精度ではない。

| 位置 | 旧方式・静止 | 改善後・静止 | 旧方式・回転 | 改善後・回転 |
| --- | ---: | ---: | ---: | ---: |
| 胴体と重ならない | 0.0% | 100.0% | 0.0% | 92.0% |
| 胸の前・カメラ側 | 100.0% | 100.0% | 10.7% | 84.0% |
| 胸の前・中間 | 100.0% | 100.0% | 14.7% | 77.3% |
| 胸の直前 | 0.0% | 100.0% | 4.0% | 92.0% |

全体は旧方式172/600 = **28.7%**、改善後559/600 = **93.2%**。改善後は実ワーカーで1800フレーム全て再生した出力（`Experiments/RuntimeV2/Fist/Predictions.csv`）。旧方式は以前のFFmpeg縮小入力・分類スコア0.65で、OpenCV縮小での再実行では171/600となった1フレーム差がある。改善後は高解像度と掌面の幾何判定を併用しており、分類だけの比較ではない。目標95%との差は1.8ポイント残る。

別の混合録画の目視確認済みサンプルでは、グーの認識13/20 = 65.0%から20/20 = 100.0%、パーの誤GRABは0/20 = 0.0%のまま。さらに初回録画の目視パー16枚も幾何判定で誤GRABなし。混合録画の未目視PROBE全体ではパー指示299枚で誤GRAB0、グー指示301枚で全てGRABだった。目視結果と指示ラベルの結果を合算して確定精度としない。

同じ最新録画の偶数PROBE300枚に限って入力頻度を比較すると、全入力281/300 = 93.7%、隔フレーム入力271/300 = 90.3%。回転追跡の履歴を失わないよう、実機の100ms送信制限を削除した。センサー自体は15 FPS、推論待ちキューは最新1枚までとする。実ワーカーの往復中央値は約21ms（カメラ取得・画像縮小・Unity処理を除く）。実機の精度・遅延は別途確認が必要。

採用しなかった案:

- 4本中3本だけの屈曲判定は、1本を伸ばした状態をGRABにするため不採用。
- 200msのGRAB保持は97.3%になったが、解放途中の映像で明確なパーをGRABのままにする例を確認したため不採用。
- 90度回転した画像を追加認識する案は93.8%で、推論を2回行うコストに対する改善が小さいため不採用。

検証は合成座標の単体テスト8件、掌面の独立計算との28,339手一致、実ワーカーの全フレーム再生、Unityでのコンパイルを実施。親指のみを伸ばす姿勢など多様な非グーや人物の違いは未検証。実験中にMediaPipeの `ConcatenateTensorVectorCalculator` が所有権の内部例外で終了した例があり、別プロセスでの再実行は完了したが、原因・発生率は未解明。

## 胸前での追跡の改善

別のライブ試行の120秒のメタデータでは、骨格がある1737行中、同じ人物のRGB結果が750ms以上古い行が131、鮮度内でも対象が選ばれない行が235あった。骨格の手や手首がlow confidenceになるとRGB自体を送信しない旧処理が一部に影響する。また、ユーザーの画面録画では膝上の反対の手を選ぶ疑いが見られた。操作ラベルがないため、このメタデータは正答率には使わない。

RGB送信をconfidence1以上で継続し、右手首を優先した照合と反対手首の候補拒否、曖昧な場合のUNKNOWNを追加した。全画面で候補が得られないときは右手の目標付近を切り出して再検出する。新しい14件の合成テストでは、反対手の拒否、クロップの座標復元、全画面のFREEをクロップで上書きしないこと、状態を保持しないことを確認した。

以前と同じ固定目標で実ワーカーを再生すると、最新600枚は562/600 = **93.7%**、旧UNKNOWNの3枚がクロップでGRABになり、旧NON_GRABの38枚は変わらなかった。混合録画の目視OPEN20/CLOSED20と指示OPEN299枚の判定も変わらず、全1799枚で旧NON_GRAB928枚を維持した。未ラベルの準備区間でUNKNOWNからGRABへ変わった1枚の正誤は未確認。

さらに、保存済みKinectキャリブレーションとDepthからBody Tracking SDKを再実行し、左右の実際の手首投影で比較した。最新600枚は561/600 = **93.5%**。固定目標による93.7%とは入力条件が異なる。DirectML再生を225枚ごとに分割し30枚のウォームアップを入れたため、区間をまたぐ人物IDの連続性は保証しない。1800枚中1799枚のRGB・depth時刻は元Frames.csvと一致。末尾1枚はネイティブ処理でアクセス違反が再現し、CPUで得た代替結果は混ぜず、対象欠落のUNKNOWNとして600枚の分母に含めた。実機の非同期処理と今回の胸前対策の体感は、帰宅後の確認が必要。

`--targets-csv` の任意列 `targetJoint`（0=手首、9=手の中心）、`otherWristX`、`otherWristY` で同じ照合条件を再生できる。古い固定座標データは既定の9を使い、反対手の座標は未指定のため取り違え対策の検証には使わない。

混合録画でも実骨格投影を取得し、1799フレーム全ての時刻を照合した。目視OPEN20枚は17 FREE・3 UNKNOWN・誤GRAB0、目視CLOSED20枚は15 GRAB・3 FREE・2 UNKNOWN（握り認識75%）。5件の見逃しは全て片手で反対の手を覆う条件に集中する。重ね合わせ監査では3枚で操作右手ではなく手前の左手を選択していた。旧方式のHand15投影でも同じ5枚はGRABにならず、固定座標の評価だけでは骨格との対応付けの失敗を見逃していた。

この残る問題は解決済みではない。両腕への距離差を厳格化すると誤った手は棄却できるが、右手も棄却されUNKNOWNが増える。RGBの位置を継続追跡する試作も改善せず、いずれも採用していない。新しい胸前対策が実機でどの程度安定するか、両手を重ねた場合の対応付け、異なる人物・服装・距離への一般化は未確認。単一の「精度95%」として全条件をまとめない。
