# Voskの停止・容量保護

## 構成

- `VoskOfflineVoiceCommands`：Unity側のマイク、イベント、起動待機、停止要求を担当。
- `VoskVoiceSession`：専用スレッドがモデルと認識器を生成し、認識処理から解放まで所有する。バックグラウンド処理からUnity APIは呼ばない。
- `VoskModelPreparation`：ZIPを64KiBずつファイルへ展開する。ZIP全体や展開データ全体をメモリに保持しない。

既存のInspectorイベント、モデルZIP名、Kinectゲート、キーボード試験の設定は維持する。

## 停止と再起動

Play終了、コンポーネント無効化、破棄、アプリ終了、Editorのコード再読み込み時に停止を要求する。停止要求は繰り返しても安全。読み込み中に終了した場合も、モデル生成から戻った専用スレッド自身が解放する。

メインスレッドが使用中の認識器・モデルを解放することはない。停止待ち200msで終わらなくても、所有者と参照を維持する。ZIPの準備開始から認識器→モデルの解放まで、プロセス単位の名前付きMutexとキャッシュ内の排他ファイルを保持する。同じUnity内の重複起動に加え、同じキャッシュを使う別プロセスの同時起動も拒否する。同じセッションの二重Startも拒否する。停止後の認識結果は捨てる。

準備開始前からキャッシュに `.vosk-session-<PID>-<起動時刻>.active` を置き、解放を確認できなかった場合は残す。同じUnityプロセスではコードの再読み込み後もZIP準備・モデル生成を拒否する。Unityプロセスを終了し、次のプロセスで起動するまでこのガードは解除しない。過去プロセスの小さなガードファイルは自動削除しない。

**Voskのネイティブ読み込み呼び出しを途中で強制中断する仕組みではない。** 停止・タイムアウト後もその呼び出しが戻るまで待ち、戻った時点で解放する。ネイティブコードの永久停止、アクセス違反、Unityプロセスの強制終了までアプリ内の後処理で保証することはできない。

## 上限と保護

- モデル起動の待機：既定180秒（InspectorのModel Load Timeout Seconds）。時間切れで停止要求し、自動再試行しない。
- 音声入力：最大32チャンク、1チャンク64KiB以下。認識結果：最大32件、1件16KiB以下。内部状態ログ：最大32件。
- 音声処理が追いつかない場合は入力を捨て、警告を最大10秒間隔に制限する。認識処理例外はセッションを終了し、例外の無限出力を防ぐ。
- モデルZIP：最大10,000エントリー、展開合計8GiB。展開前に「展開予定量＋2GiB」の空きが必要。展開中は16MiBごとに2GiBの残容量を確認する。
- 読み込み前にキャッシュとシステムドライブに2GiBの空きが必要。Unity側でも2秒ごとに確認し、下回れば停止要求する。
- Windowsでは読み込み前に、物理メモリの空き `max(512MiB, モデルファイル合計×2)` とコミットの空き `モデルファイル合計×3＋512MiB` を参考値として確認する。下回る場合やメモリ情報を取得できない場合は警告だけを出し、単一モデルの読み込みを継続する。これらはVoskの必須条件ではなく、実際の必要量や上限を示す値でもない。実際の読み込みエラーは従来どおり停止・解放処理へ進む。
- マイクが見つからなければモデルを読み込まない。マイク録音とAudioClipは停止時に終了・破棄する。

## ZIPキャッシュ

必要なモデルファイルが存在し空でなければ、既存の展開済みフォルダを再利用する。既存キャッシュを自動で上書きしない。プロセス間の排他ファイルで同時展開を防ぐ。

初回のみ一時フォルダに展開し、検証後に正式フォルダへ移す。キャンセル・展開エラーでは、その試行で作成した一時フォルダだけを削除する。ZIP内の外部へのパス、重複パス、シンボリックリンク、宣言長を超えるデータを拒否する。

異常終了で残った `<モデル名>.extracting-*` があれば、新しい展開を開始せずエラーにする。残骸の場所をログで確認し、Unityを終了した状態で内容を確認する。既存キャッシュやZIPは自動削除しない。
