# 空の音声認識結果の切り分け

VoskOfflineVoiceCommandsの「音声入力の診断ログ」をON（既定）にすると、約2秒ごとに[Vosk][Input]を出します。録音ファイルは作りません。確認後はOFFにしてログ量を減らしてください。Inspectorの「音声入力の状態」「最後の認識JSON」も確認できます。

- gate=WAITING：認識案内・起動演出・撤退・軌跡表示中など、指示を止めている状態です。操作開始後にOPENになることを確認してください。
- input：USB機器から読めた音量（dBFS）。話しても-120付近のままなら無音です。Windows側の入力機器・ミュート・入力レベル・マイク使用許可を確認します。-65未満の警告は診断上の目安で、音声を捨てるしきい値ではありません。
- mono：Voskへ渡す前のモノラル平均の音量です。inputだけ大きくmonoが著しく小さいと、左右の逆位相などで相殺されている可能性があります。現在の変換方法を勝手に変更する処理は入れていません。
- position：Unityマイクの録音位置。1秒のループなので値が戻るのは正常です。
- nativeProcessed/delta：VoskのAcceptWaveformが処理し終えたバイト数。OPENで話し、音量があるのにdelta=0が続く場合は認識側の停滞を疑います。
- partial：認識途中のJSON。確定前はpartialだけ文字が出る場合もあります。発話後に1～2秒黙ってFinal resultを確認してください。

次回は操作開始後、話しかけている間の[Vosk][Input]を2～3行と、その直後のFinal resultをそのまま共有してください。

現地で使っている大規模日本語モデルvosk-model-ja-0.22はHCLG.fstを持つ固定グラフです。この形式は実行時の語彙制限に対応しないため、通常の認識器で文字起こしし、結果をBuildPhraseMapの一覧と照合します。動的グラフのモデルだけ語彙指定付き認識器を使います。起動ログにRecognition modeを出します。単語一覧への追加はこの固定モデルの辞書を学習・更新する操作ではありません。

空のtextは単語照合前の結果です。textに言葉があるがCommand matchedがない場合は、単語の正規化と照合候補の問題を確認します。単語一覧だけの変更で空になる原因を確定したわけではなく、実機ログによる切り分けが必要です。

モデルのZIP展開・所有者・重複防止・解放処理は維持しています。Unityは起動せず、C#コンパイルと入力音量計算の独立テストを実施しました。実際の録音と音声認識は未確認です。
