# 開始前のプレイヤー認識画面

Mainの起動直後に、白背景と短い説明・人型の図・認識の進捗を表示します。Wii Fitのように落ち着いた準備画面を意図した、独自の画面です。

Azure Kinectの深度Body Trackingを使い、**同じ1人の新しい骨格フレームが3秒間安定して得られたら、ロボット視界の起動演出を挟んで海中画面へ進みます**。起動演出（既定3.2秒）の完了後に操作を解禁します。詳細は[ロボット視界の起動演出](RobotVisionStartup.md)を参照してください。Webカメラや疑似タイマーで認識したことにはしません。

椅子に座ったプレイヤーの、頭・左右の肩・胸のConfidenceがMedium以上で、座標が有効であることを確認します。骨盤・脚・足は開始条件に含めず、椅子や机で隠れていても上半身が見えれば認識を進めます。手も開始条件には含めません。フレームが0.35秒より古い、認識が途切れる、別のIDになる、複数人になる場合は進捗をリセットします。同じフレームの繰り返しやセンサー停止では進みません。

開始時に、そのBody IDをKinectScoopPoseへ引き継ぎます。認識後は既存のAzure Kinect入力を餌やりにも継続使用します。既に有効な入力がある場合、センサーを追加起動しません。無効なKinectデモを勝手に有効化することもありません。

認識待ちの間はHUDを非表示にし、視点・前進・餌やりをブロックします。音声モデルの準備は進めますが、この画面にいる間の音声を操作コマンドとして取り込みません。Time.timeScaleは変更しません。

## 実機

VoiceCommandsの **Keyboard Feeding Test ModeをOFF** にしてPlayします。椅子に座り、頭・両肩・胸がセンサーに見える位置で正面を向いてください。案内図も椅子に座った人を表示します。接続がない場合は認識画面で待機し、勝手に始まりません。Azure KinectのSDK配置・接続手順は既存のAzure Kinect導入資料に従ってください。

## ノートPCの試験

既存の **Keyboard Feeding Test ModeがON** の場合はAzure Kinect SDKを新規起動しません。白画面に試験モードであることを表示し、Gameビューで **Enter** を押すと明示的にスキップできます。この場合は実機で認識したというログ・状態にはしません。

## 設定

MainのPlay時に `PlayerRecognitionScreen` を自動生成します。秒数やフォントを保存して調整する場合は、Play前に空GameObjectへ `KinectStartupController` を1つ追加し、設定してシーンを保存してください。既に同じシーンに存在すれば二重生成しません。

開始前の画面を無効化・破棄しただけでは操作を解禁しません。通常は3秒認識、試験モード時だけEnterスキップを使用します。

## 検証

認識の継続・中断・ID変更・古いフレーム・フレーム停止・Mainの操作ゲート、着席時の骨盤・下肢欠損、上半身の低信頼度等、独立テスト32項目成功。Unity参照DLLによるプロジェクトC#コンパイル成功。

Unity・Azure Kinect SDKは起動していません。実機での認識、Gameビューでの表示は未確認です。レイアウト確認用の静止画はUnityのスクリーンショットではありません。

## 体験開始後の離席終了

実機で認識した同じ人を継続確認します。骨格・頭肩胸の認識が失われた状態、または胸が認識時より300mm以上上昇した状態が1.5秒続くと、シャットダウンして白地・水色の航行記録へ進みます。一瞬の認識抜けは猶予し、別の人には自動で切り替えません。キーボード試験でEnter開始した場合は適用しません。秒数と上昇量はKinectStartupControllerのInspectorで調整できます。実際の椅子・センサー位置に合わせた実機確認は未実施です。
