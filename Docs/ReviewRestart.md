# 軌跡画面から次の参加者へ

軌跡表示中、体験した人の着席認識が連続5秒失われると、最初の白い「椅子に座ってください」画面へ戻ります。途中で同じ人の認識が戻ればカウントは解除します。別の人の骨格への入れ替わり、立ち上がり、古い受信フレームも認識喪失として扱います。5秒のカウントは軌跡画面の表示開始後に始まります。

Play中のHierarchyでDiverRetreatを選び、DiverRetreatControllerの「軌跡画面で認識喪失から最初へ戻る秒数」で変更できます。キーボード試験・診断用認識スキップでは実際の着席認識がないため自動判定しません。Kinectなしの試験では同コンポーネントのメニュー「軌跡画面から認識画面へ戻る（テスト）」を実行してください。

戻る際はダイバーの位置・向き、軌跡・餌やりマーカー・体験時計、HUDのシャットダウン状態、骨格の選択をリセットします。操作開始時の自動前進も次の体験で再び有効です。魚の色など海中の状態は維持します。

シーン再読み込みは行いません。Voskコンポーネントを撤退時に無効化する代わりに、既存の開始ゲートで入力送信と指示の実行を止めます。VoskモデルとKinectキャプチャを次の体験でも同じ所有者で維持するため、繰り返しのZIP展開・モデル再読み込みを発生させません。異常・切断で停止済みの音声処理を勝手に再起動することはありません。

認識案内画面はScreenSpaceOverlayで表示し、ProjectionUiSettingsの投影範囲・全体倍率から独立させました。案内は画面中央へ縦横比を維持して収めます。海中HUDと軌跡の投影UI設定は従来どおりです。

確認手順：通常のKinect認識で開始→撤退→軌跡表示中に一瞬認識を外して戻す（維持）→5秒連続で離席（案内へ戻る）→次の人が3秒安定認識（再び起動）→再度撤退して新しい軌跡だけ表示されることを確認してください。Voskのモデル初期化ログが毎回増えないことも確認します。

Unityは起動せず、C#コンパイルと着席認識タイマーの独立テストを実施しました。描画・Kinect実機・複数人での連続運転は未確認です。
