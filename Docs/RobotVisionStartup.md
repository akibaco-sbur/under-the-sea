# ロボット視界の起動演出

ダイバーはロボット、DiverViewはその光学視界という設定です。

開始は **着席プレイヤーをAzure Kinectで3秒安定認識 → 約3.2秒の視界起動 → 操作解禁** の順になります。

## 演出

暗い視界が中央から上下に開き、外周フレーム、方位目盛、音声・移動表示、腕・姿勢表示、操作案内が順番に現れます。中央の起動案内と進捗は最後に消えます。視点を強制的に揺らす演出、強い点滅、全面の常時走査線は使っていません。

これらは表示の起動演出です。実際に取得できていない電池残量や処理の完了率を装うものではありません。音声モデルがまだ準備中であれば、その状態をHUDにそのまま表示します。

## HUDの追加要素

- 明るいシアンの外周コーナー、左右の目盛、小さな中央の光学ブラケット。
- 腕の追跡中・待機中・キーボード試験の区別。
- 実際のカメラの上下角度。
- ダイバー全体の開始時の高さを基準にした相対的な深さ。海面からの絶対深度ではありません。
- 実際の速度比に連動するバーと操作開始後の稼働時間。

中央の海中視界と餌やり対象を見やすくする配置は維持します。

## 操作の保護

起動演出が完了するまでは、移動・視点指示・餌やりは解禁しません。実機では起動中も同じ人物の新しい上半身フレームを確認します。最後の瞬間に認識が失われている場合は操作を解禁しません。認識不良が0.6秒続く場合は認識画面へ戻り、再度3秒確認します。

HUDが無効化・破棄されて演出を完了できなくなった場合も、認識画面へ戻します。Kinect入力、Voskモデルを追加起動する処理はありません。

## 調整と試験

`KinectStartupController > ロボット視界の起動秒数`（既定3.2秒）で調整できます。Play後も設定を残す場合は、Play前に同コンポーネントを1つ置いて設定します。

Keyboard Feeding Test ModeがONの場合は、認識画面でEnterを押すと実機認識を省略し、同じ起動演出を確認できます。起動演出そのものは省略しません。

表示段階の順序、暗幕の開始・終了、時間の不正値、認識不良時の操作解禁禁止など、模擬テスト44項目成功。Unity参照DLLによるプロジェクトC#コンパイル成功。

Unityは起動・操作していません。プレビューGIF/PNGはコード配置をもとにしたイメージであり、Unityのキャプチャではありません。実際のGameビュー、実機の認識継続、海中背景での読みやすさは未確認です。
